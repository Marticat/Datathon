# Проверка внешних разговоров — 8 ноября 2026

Проверены **три полных чата ABCD и два полных звонка Perit**. Это дополнительные данные для проверки работоспособности, не DEV/PROD и не официальный Ground Truth. Исходники, лицензии, версии и SHA-256 — в [samples](../samples/README.md). [Машинный отчёт](external-validation-results.json) содержит фактические ответы, доказательства, модель/digest, версии инструкций и время каждого запуска.

Все пять оценок получены настоящими запросами локальной `qwen3.5:9b`. Звонки сначала обработаны Whisper Small на CPU; затем роли подтверждены по приветствию оператора и вопросам клиента, без переписывания распознанного текста. Сохранённые отчёты не загружаются как оценки в чистое приложение: повторная проверка запускает модель заново.

## Исправленный дефект аудиопроцесса

Обычный режим смешивал стереоканалы перед распознаванием и акустическим разделением. На **обоих** примерах результат содержал один известный голос `speaker_0` плюс неопределённые фрагменты, несмотря на выбор двух говорящих. В первом звонке приветствие оператора и начало ответа клиента попали в один сегмент. Такой черновик нельзя автоматически считать корректно разделённым диалогом.

Добавлен явный режим «Стерео: по одному голосу на канале». Он применим только к записям с таким устройством каналов, как эти Perit. Два канала распознаются независимо на исходной временной шкале; идентичность канала сохраняется даже при одновременной речи. Программа по-прежнему не угадывает бизнес-роли.

| Проверка | Первый звонок | Второй звонок |
|---|---:|---:|
| Длительность, секунды | 167.064 | 167.160 |
| Известных голосов в обычном режиме | 1 | 1 |
| Известных голосов в раздельном режиме | 2 | 2 |

На первом звонке канал 0 содержит приветствие и представление Caleb, канал 1 — запрос на смену пароля. На втором канал 0 содержит представление Ian, канал 1 — вопросы о визите техника. Привязки к записи и роли сохранены после публикации и дальнейшей AI-оценки. Низкая уверенность ASR не считается доказанной ошибкой распознавания; WER/DER не измерялись, независимого пословного эталона нет.

## Смысловые ошибки, которые остались

1. **Подмена проверки личности поиском карточки.** В ABCD 3592 система обосновала c3=Да тем, что аккаунт найден (реплика 7). Это не подтверждает успешную идентификацию. В ABCD 9489 она аналогично использовала имя/ID и открытие аккаунта. Для первого случая спорно, требовалась ли идентификация вообще; для второго статус возврата персонализирован, но смысл «everything in order» допускает разную трактовку. Надёжный вывод: приведённое обоснование «найдена карточка ⇒ личность подтверждена» недостаточно.
2. **Неполное применение условия завершения.** В ABCD 9489 c7=Да объяснён только прощанием в реплике 21. Официальный критерий дополнительно требует итог либо предложение дальнейшей помощи. В ABCD 3592 итог и прощание действительно есть (27–28); в ABCD 3695 модель корректно поставила Нет.
3. **Не все существующие ссылки доказывают вывод.** В первом Perit для эмпатии приведена благодарность клиента, а не реплика оператора. Для консультации модель иногда ссылается на вопрос, а не на его решение. Проверка существования ID защищает от выдуманных цитат, но не доказывает смысловую достаточность ссылки.
4. **Лишний вопрос может быть ошибочно засчитан как выяснение потребности.** В ABCD 3695 общая просьба сообщить срок действия уже сформулирована, но модель оценила уточнение «вы пробовали код?» как необходимое. Это спорный случай применения N/A, требующий ручной калибровки.
5. **Риск переоценки устной речи и контекста.** Во втором Perit клиент выражает неудобство из-за четырёхчасового окна, а объяснение эмпатии утверждает, что недовольства не было. В первом упоминание номера обращения интерпретируется как секретный код. Имена, буквенные коды и числа в ASR нуждаются в прослушивании.

Три ABCD-диалога отдельно разобраны до просмотра ответов модели. Это самостоятельная проверка, **не разметка организаторов**. Неоднозначные случаи не используются для заявления процента точности.

Дополнительная инструкция против ошибок идентификации/завершения проверена на двух завершённых повторных прогонах ABCD 3592 и 9489: ответы c3/c7 не изменились. Эксперимент остановлен, инструкция **не включена** в рабочий оценщик. Мы не меняли оценки вручную и не подгоняли правило под ID примеров.

## Готовность для проверяющих

Исправлены первый экран без DEV URL, выбор внешней группы, устаревший флаг грубой ошибки после новой версии чек-листа, восстановление после удалённой аудиозаписи. Для ABCD без времени сообщений отображается «Время не указано», без выдуманных секунд и NaN. Стереоголоса подписаны «Левый канал» и «Правый канал», роли подтверждаются вручную. Добавлены безопасная диагностика `npm run doctor`, открытые примеры и инструкция [запуска для жюри](judge-quickstart.md). Конфигурация `.env` при подготовке больше не перезаписывается безусловно.

Проверены отдельно: чистая копия без `.env`/частных данных/зависимостей проекта; импорт нового диалога; очередь; доказательства; апелляция и сохранение решения; новый критерий и вес; повторная оценка; фильтры; мобильный экран; аудиоплеер, роли, разделение сегмента и публикация. Автоматические браузерные проверки используют явно тестовый адаптер только внутри изолированного теста; описанные выше пять оценок — реальные локальные прогоны.

Для демонстрации: сначала `npm run doctor`, затем `npm start`, в другом терминале `npm run examples -- import`. Для аудио — `npm run examples -- audio`, проверить роли на `/audio`, подтвердить диалог и запустить оценку. Не запускать тяжёлые проверки параллельно контрольной сдаче. Полный первый запуск всё ещё требует установленной локальной модели; скачивание нескольких гигабайт не входит в обещание «мгновенного старта».
