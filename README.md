# CQA · контроль качества диалогов

Проект команды **orleugpt** для Freedom Datathon. Приложение оценивает разговор оператора с клиентом по чек-листу, объясняет каждый балл ссылками на реплики и позволяет подать апелляцию. Поддерживаются русский, казахский и английский языки.

**Работает локально:** интерфейс и сервер на вашем компьютере, оценка через Ollama, распознавание аудио через Whisper. Облачный API-ключ не нужен. У приложения нет обязательных npm-зависимостей и этапа сборки.

## Запуск с нуля

Основной сценарий проверен на **Windows / PowerShell**. Команды Git, Ollama и npm в этом разделе одинаковы для Windows, macOS и Linux. Скрипты `.ps1` ниже предназначены для Windows.

### 1. Установите инструменты

| Инструмент | Для чего нужен | Версия / установка |
|---|---|---|
| Git | Скачать проект | [Установить Git](https://git-scm.com/downloads) |
| Node.js и npm | Запустить приложение | [Установить Node.js LTS](https://nodejs.org/en/download); проект требует **20.20+** |
| Ollama | Запустить локальную AI-модель | [Установить Ollama](https://ollama.com/download); проект требует **0.40.15+** |
| Python | Только для распознавания аудио | **3.10+**; для текстовых диалогов не нужен |

После установки откройте **новый терминал** и проверьте:

```sh
git --version
node --version
npm --version
ollama --version
```

Для модели понадобятся несколько гигабайт свободного места. Скорость зависит от компьютера и длины диалогов. Реальные прогоны выполнялись на NVIDIA RTX 4060 с 8 ГБ VRAM; это проверенная конфигурация, а не гарантия минимальных требований. Без достаточной памяти оценивание может идти медленно или завершаться ошибкой.

### 2. Скачайте проект

```sh
git clone https://github.com/Marticat/Datathon.git
cd Datathon
```

Все дальнейшие команды выполняйте **из этой папки**, где находится `package.json`. Основная ветка — `main`.

### 3. Подготовьте локальную модель

Откройте установленное приложение Ollama. Если служба ещё не работает, запустите её в отдельном терминале и оставьте его открытым:

```sh
ollama serve
```

В другом терминале скачайте модель:

```sh
ollama pull qwen3.5:9b
ollama list
```

Дождитесь окончания загрузки: в списке должна появиться **`qwen3.5:9b`**. Скачивание нужно один раз; при повторном запуске уже установленные веса используются локально. Если `ollama serve` сообщает, что порт 11434 занят, Ollama может уже работать — второй экземпляр не нужен.

### 4. Запустите приложение

Из папки `Datathon`:

```sh
npm run doctor
npm start
```

Откройте **[http://127.0.0.1:3000](http://127.0.0.1:3000)**. Терминал с `npm start` должен оставаться открытым.

`doctor` проверяет окружение и наличие модели, ничего не устанавливает и не запускает оценивание. Ожидаемый итог — **«Готовность текстового оценивания: ДА»**. Предупреждения `WARN` про Python и аудиомодели допустимы, если вы проверяете только чаты.

**Для первого запуска `.env`, URL организаторов и `npm install` не нужны.** Даже без модели интерфейс откроется и позволит загрузить диалоги; для получения AI-оценок нужна работающая модель.

## Первая оценка

В репозитории уже есть **три открытых чата ABCD**. Для их проверки не нужен доступ к данным организаторов.

1. Оставьте приложение запущенным.
2. Откройте второй терминал в папке `Datathon` и выполните:

   ```sh
   npm run examples -- import
   ```

3. Откройте **[набор EXTERNAL-ABCD](http://127.0.0.1:3000/?group=EXTERNAL-ABCD)**.
4. У нужного диалога нажмите **«Анализ» → «Оценить с ИИ»**.
5. Дождитесь результата. Раскройте критерий, чтобы увидеть объяснение и перейти к реплике-доказательству.

Для пакетной оценки трёх примеров через терминал:

```sh
npm run examples -- evaluate
```

Это запускает настоящую локальную модель по официальному чек-листу. Готовые оценки в приложение не подставляются. Очередь сохраняется на сервере и продолжает работать после закрытия вкладки.

Источники, лицензии и преобразования примеров описаны в [samples/README.md](samples/README.md). Это внешние проверочные разговоры, **не эталонные оценки и не конкурсные DEV/PROD**.

## Как пользоваться

| Адрес | Что находится на странице |
|---|---|
| [Главная — `/`](http://127.0.0.1:3000/) | Диалоги, анализ, фильтры, апелляции и чек-листы |
| [Настройки — `/classic`](http://127.0.0.1:3000/classic) | Выбор локальной модели, импорт через API организаторов, история запусков |
| [Аудио — `/audio`](http://127.0.0.1:3000/audio) | Загрузка записи, распознавание, проверка текста и назначение ролей |

- **Свой JSON:** нажмите «Загрузить диалог» слева внизу. Принимается ответ API организаторов или массив диалогов. Пример готового файла: [samples/abcd/conversations.json](samples/abcd/conversations.json). Для аудиофайла используйте страницу `/audio`.
- **Нужный набор:** выберите его в списке на странице «Диалоги». Список появляется, когда наборов несколько; последний выбор запоминается в браузере.
- **Грубые ошибки:** включите соответствующий фильтр. Он учитывает первоначальную находку модели, даже если её позже пересмотрели.
- **Апелляция:** раскройте критерий → «Оспорить» → укажите причину. Решение принимается отдельно в блоке «Апелляция и решение проверяющего» под анализом. Первоначальная оценка сохраняется.
- **Изменение чек-листа:** «Чек-листы» → «Список чек-листов» → «Копия выбранного». Задайте название, измените критерии или веса и сохраните. Официальный стандарт защищён от изменения. Новая версия требует повторного оценивания.

Во время активной проверки дождитесь её завершения перед переключением набора или чек-листа. Удаление собственного чек-листа скрывает его из списка в этом браузере; серверная история остаётся.

Для защиты: [сценарий живой демонстрации на пять минут](docs/demo.md).

## Настройки `.env`

Этот шаг нужен для своих адресов, данных организаторов, длинных диалогов или отдельного Python. Создайте `.env`, **не перезаписывая существующий файл**.

Windows / PowerShell:

```powershell
if (!(Test-Path -LiteralPath '.env')) { Copy-Item -LiteralPath '.env.example' -Destination '.env' }
```

macOS / Linux:

```bash
if [ ! -f .env ]; then cp .env.example .env; fi
```

| Переменная | По умолчанию | Когда менять |
|---|---|---|
| `PORT` | `3000` | Порт приложения занят |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Ollama слушает другой локальный адрес |
| `OLLAMA_MODEL` | `qwen3.5:9b` | Начальная модель при создании состояния |
| `OLLAMA_CONTEXT` | `16384` | Для длинных диалогов установите `32768`; это требует больше памяти |
| `DATASET_URL` | Пусто | Подписанный GET-адрес DEV, выданный организаторами |
| `CQA_PYTHON` | `python` | Путь к Python, которым установлены аудиозависимости |
| `CQA_URL` | `http://127.0.0.1:3000` | Адрес приложения для команд `examples`, `evaluate` и `submit`, если изменили порт |

После изменения настроек остановите свой сервер через `Ctrl+C` и снова выполните `npm start`. Дождитесь окончания активной проверки перед плановым перезапуском.

**Уже выбранная модель хранится в состоянии приложения.** Если приложение запускалось раньше, меняйте модель на `/classic`: одной правки `OLLAMA_MODEL` недостаточно. Для длинного DEV-звонка в проверенном прогоне использовался контекст `32768`; транскрипт не обрезался.

Пример смены порта в `.env`:

```dotenv
PORT=3001
CQA_URL=http://127.0.0.1:3001
```

После перезапуска открывайте `http://127.0.0.1:3001`. Не публикуйте `.env` и подписанные ссылки организаторов.

## Распознавание аудио (необязательно)

Текстовая оценка работает без этого раздела. Для загрузки записей понадобятся **Python 3.10+**, аудиобиблиотеки и отдельные модели. На Windows использовался Python 3.10; CPU-распознавание может занимать несколько минут.

### Windows / PowerShell

Проверьте интерпретатор и запустите установку из папки проекта:

```powershell
python --version
./scripts/setup-audio.ps1
```

Если нужный Python не выбран по умолчанию, передайте **свой реальный путь**:

```powershell
./scripts/setup-audio.ps1 -Python 'C:/path/to/python.exe'
```

Тот же путь укажите в `.env`: `CQA_PYTHON=C:/path/to/python.exe`. Скрипт скачивает библиотеки в `.local/audio-python`, модели — в `.local/audio-models`.

### macOS / Linux

Установите зависимости в отдельное окружение:

```bash
python3 -m venv .local/audio-venv
.local/audio-venv/bin/python -m pip install -r scripts/requirements-audio.txt
.local/audio-venv/bin/python scripts/setup_audio.py
```

В `.env` укажите `CQA_PYTHON=.local/audio-venv/bin/python`. Эти команды предназначены для Unix-систем; полный аудиопрогон проекта проверялся на Windows.

### Проверка записи

После установки перезапустите приложение, выполните `npm run doctor` и откройте `/audio`. Поддерживаются OGG, MP3, WAV, M4A, MP4, FLAC, WebM и Opus; ограничение — **80 МБ и 20 минут**.

1. Загрузите запись и дождитесь распознавания.
2. Проверьте текст и назначьте голосам роли оператора и клиента. При необходимости исправьте или разделите реплики.
3. Подтвердите черновик. Диалог появится в наборе `AUDIO`.
4. Откройте его анализ и запустите AI-оценку.

Если точно известно, что **в каждом стереоканале записан отдельный человек**, выберите «Стерео: по одному голосу на канале». Для обычной смешанной записи оставьте стандартный режим. Левый/правый канал не определяет роль оператора автоматически.

Два открытых звонка Perit можно загрузить командой:

```sh
npm run examples -- audio
```

Она выбирает раздельные каналы для этих записей и выводит ссылки на черновики. Роли всё равно нужно проверить вручную. Исходное аудио и исходный результат распознавания сохраняются отдельно от правок.

## Если что-то не работает

| Симптом | Что сделать |
|---|---|
| `node`, `npm`, `git` или `ollama` не найдены | Установите инструмент и откройте новый терминал. Проверьте команды из первого шага. |
| PowerShell блокирует `npm.ps1` | Используйте `npm.cmd start` или `npm.cmd run doctor`. Для `.ps1`-скриптов соблюдайте политику вашего компьютера; обычный текстовый запуск не требует этих скриптов. |
| `ENOENT … package.json` | Перейдите в папку `Datathon`, содержащую `package.json`. |
| Ollama недоступен | Откройте Ollama или запустите `ollama serve`; проверьте `OLLAMA_URL`, затем повторите `npm run doctor`. |
| Модель не установлена | Выполните `ollama pull qwen3.5:9b`, проверьте `ollama list` и выбор модели на `/classic`. Облачные модели здесь не поддерживаются. |
| Не хватает памяти | Закройте другие тяжёлые программы. Можно установить `ollama pull qwen3.5:4b` и выбрать её на `/classic`; качество этой модели нужно проверять отдельно. |
| `exceeds the available context size` | Установите `OLLAMA_CONTEXT=32768`, перезапустите сервер и повторите оценку сбойного диалога. Не удаляйте части транскрипта. |
| `EADDRINUSE`, порт 3000 занят | Если CQA уже запущен, откройте его. Иначе измените `PORT` и `CQA_URL`, как показано выше. |
| Страница пустая или нет диалогов | Импортируйте примеры, откройте набор `EXTERNAL-ABCD` или загрузите свой JSON. Результаты сдачи сами не наполняют интерфейс. |
| Запрашивается URL организаторов | Для публичных примеров он не нужен: откройте главную без параметра `group`, затем загрузите JSON или выполните импорт примеров. |
| Оценка идёт долго | Посмотрите очередь на `/classic`. Задания выполняются последовательно; CPU и длинный контекст увеличивают время. Не запускайте дополнительные тяжёлые оценки параллельно. |
| Не работает аудио | Сверьте Python в установке и `CQA_PYTHON`, повторите установку аудио и диагностику. |
| После обновления виден старый интерфейс | Обновите страницу без кэша: `Ctrl+F5` на Windows. |

## Повторный запуск и обновление

Откройте Ollama, затем из папки проекта выполните `npm start`. Модель и зависимости скачивать заново не нужно. Остановка приложения — `Ctrl+C` в его терминале.

Для обновления сначала дождитесь окончания задач и остановите приложение:

```sh
git pull --ff-only origin main
npm start
```

Если Git сообщает о ваших локальных изменениях, сохраните их перед обновлением. Не сбрасывайте рабочую папку ради запуска.

<details>
<summary>Альтернатива для Windows: переносимая установка Ollama</summary>

Если не хотите устанавливать Ollama отдельно, после установки Git и Node.js используйте:

```powershell
./scripts/setup-local.ps1
./scripts/start-local.ps1
```

Первый скрипт скачивает официальный Windows x64 runtime и проверяет SHA-256. Второй запускает локальный сервис, скачивает модель и запускает CQA. При запуске собственного сервиса веса хранятся в `.local/models`; уже запущенный Ollama не перезапускается и использует своё хранилище.

Для последующих запусков с уже скачанной моделью:

```powershell
./scripts/start-local.ps1 -SkipModel
```

## Результаты сдачи

В репозитории опубликованы результаты команды **orleugpt**:

- [results/dev/results.json](results/dev/results.json) — **65 диалогов**, 60 чатов и 5 звонков, без ошибок обработки.
- [results/prod/results.json](results/prod/results.json) — **10 контрольных чатов FBroker**, без ошибок обработки.

Это сохранённые AI-оценки по формату организаторов, **не Ground Truth**. Чистый запуск не импортирует их в интерфейс: для новой оценки нужны исходные диалоги. Исходные DEV/PROD и SWAP в Git не включены; SWAP не входит в PROD.

Для собственной повторной выгрузки при уже импортированном DEV и наличии настоящего контрольного файла:

```sh
npm run submit -- dev --evaluate
npm run submit -- prod --input .local/prod.json --evaluate
```

Эти команды запускают оценивание и записывают соответствующие `results.json`; они **не выполняют commit и push**. Проверка `--check` требует исходного набора в приложении и локальной квитанции экспорта, поэтому на чистом клоне сначала нужна собственная выгрузка. Полный порядок — в [docs/submission.md](docs/submission.md).

## Данные и ограничения

- Состояние приложения, диалоги, очередь, оценки и апелляции: `.local/state.json`. Записи и черновики: `.local/audio/`. Для переноса сохраните эти данные отдельно при остановленном сервере. Не запускайте два экземпляра с одним состоянием.
- `.env`, `.local/`, модели и частные исходники игнорируются Git. Папки **`samples/` и `results/` включены** в репозиторий.
- Приложение слушает только `127.0.0.1`; входа по логину нет. Описанный запуск предназначен для локальной демонстрации, а не публичного сервера.
- Модель Qwen — универсальная, а не специально обученная на чек-листе Freedom. Она может ошибаться в идентификации, завершении разговора и выборе доказательств. Реальные наблюдения: [отчёт по ABCD и Perit](docs/external-validation.md).
- N/A исключает критерий из применимых весов; грубое нарушение передаётся отдельным флагом. Итог: `round(100 × Σ(вес × нормированный ответ) / Σ(применимый вес), 2)`.
- Аудиораспознавание может ошибаться в словах и голосах. Черновик и роли требуют проверки человеком; система не устанавливает факты, которых нет в записи.

Размещение в Dynamics 365 или на другом origin требует отдельной настройки сервера, CORS и доступа. Текущая конфигурация предназначена для локального запуска.
