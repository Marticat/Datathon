# CQA · Freedom Datathon

Локальное рабочее место контроля качества клиентских диалогов. Транскрипт → оценка по редактируемому чек-листу → доказательства → апелляция → решение проверяющего.

## Что работает

- Импорт JSON организаторов, загрузка группы DEV/контрольной группы через сервер; RU/KZ/EN, чат и запись звонка.
- Восемь официальных критериев, точные ступени шкал, N/A, пропорциональное перераспределение весов. Грубая ошибка — отдельный флаг.
- Настоящие запросы к локальной модели Ollama с JSON Schema. Нет подставленных оценок или скрытого облачного резервного режима.
- Версии чек-листа, новые критерии через интерфейс, новые оценки без использования старого кэша.
- Переход к исходным репликам, неизменяемые снимки диалогов и первоначальные оценки.
- Апелляции по критерию, решение с причиной и пересчёт; предыдущие решения остаются в истории.
- Последовательная пакетная очередь, отдельное сохранение результатов, возобновление после перезапуска, явные ошибки.
- Выгрузка JSON для анализа и передачи результатов. Исходные AI-оценки отделены от ручного пересмотра.

## Быстрый запуск

**Для проверяющих:** [пошаговый запуск и устранение проблем](docs/judge-quickstart.md). В репозитории есть [два открытых звонка Perit и три чата ABCD](samples/README.md), которые можно проверить без доступа к частному DEV.

Нужны Node.js **20.20+** и Ollama **0.40.15+**. У приложения нет обязательных npm-зависимостей и шага сборки.

```powershell
if (!(Test-Path -LiteralPath '.env')) { Copy-Item -LiteralPath '.env.example' -Destination '.env' }
# В .env укажите DATASET_URL — адрес кнопки GET для DEV из Student Guide.
npm start
```

Откройте **http://127.0.0.1:3000**. Для импорта можно указать группу DEV или загрузить JSON вручную. Интерфейс работает без модели; вычисление оценки станет доступно после установки модели.

В другом терминале: `npm run doctor` проверяет готовность без загрузок и изменения данных; `npm run examples -- import` добавляет три публичных чата в группу `EXTERNAL-ABCD`; `npm run examples -- audio` ставит две записи Perit на распознавание. Для независимой проверки используются новые реальные запросы модели, готовых баллов в примерах нет.

Главная страница сделана по дизайну «CQA — шаблон интерфейса» (`public/cqa.css` — стили макета без изменений, `public/cqa-extra.css` — дополнения для живых данных). В ней четыре раздела: «Диалоги» (список, фильтры, пакетная оценка), «Анализ» (расшифровка, дорожка записи с метками доказательств, кольцо итога, критерии по секциям, окно апелляции, решение проверяющего), «Апелляции» и «Чек-листы» (критерии по секциям, ступени шкалы с описаниями, N/A, грубая ошибка, применение новой версии к диалогам). Роль «Аналитик»/«Проверяющий» переключается в боковой панели: подача апелляции и решение — отдельные действия. Шрифт Inter не подгружается, потому что CSP разрешает только локальные ресурсы; используется системный шрифт из того же стека. Данные идут через адаптер `public/cqa-api.js`. Фиктивный сервер и сохранённые оценки из архива не используются. В меню «Модель, импорт и история» доступен расширенный экран `/classic`: настройка Ollama, загрузка JSON и история запусков. Изменение любого поля чек-листа создаёт новую версию и требует полной повторной оценки. Задачи сохраняются на сервере и продолжаются после закрытия вкладки.

Для демонстрации доступны поиск по ID/репликам, язык и фильтр «Грубые ошибки AI». Он сохраняет первоначальную находку модели даже после изменения флага проверяющим. Пятиминутный сценарий защиты: [docs/demo.md](docs/demo.md). Итоги настоящих локальных прогонов и известные смысловые ошибки: [docs/verification.md](docs/verification.md).

## Аудио → текст → роли → оценка

Если известно, что стереозапись содержит **по одному участнику на каждом канале**, выберите соответствующий тип записи. Каждый канал распознаётся отдельно: это сохраняет двух говорящих и одновременную речь без акустического угадывания. В обычном режиме применяется разделение голосов в общем звуке. В обоих режимах роль оператора/клиента подтверждается вручную. Раздельный режим требует примерно вдвое больше работы распознавателя и не подходит для обычного стереомикса с обоими голосами на обеих дорожках.

В меню «Загрузить аудио» или по адресу `/audio` можно загрузить OGG/MP3/WAV/M4A/FLAC/WebM/Opus до 80 МБ и 20 минут. Для локальной обработки нужен Python 3.10+:

```powershell
./scripts/setup-audio.ps1
# Если нужный Python не используется по умолчанию:
./scripts/setup-audio.ps1 -Python 'C:/path/to/python.exe'
```

Укажите этот же интерпретатор в `CQA_PYTHON` файла `.env`, если требуется. Установка загружает модели и зависимости в `.local`. Обработка использует CPU и не отправляет аудио в облако. Whisper Small распознаёт слова, sherpa-onnx выделяет голоса; язык `KZ` соответствует `kk` в Whisper. Одноголосая запись допустима. Для известного количества голосов можно выбрать 1–4 вместо автоматического определения.

Проверьте черновик: назначьте роли голосам, исправьте текст, исключите лишнее. Если голоса перепутаны, измените роль конкретной реплики или разделите склеенную реплику. Неизвестные голоса и возможные наложения отмечаются для ручной проверки. После подтверждения создаётся диалог группы `AUDIO`, доступный обычному оценщику и апелляциям. Черновики и задания сохраняются после перезапуска; ASR-оригинал остаётся отдельно от правок.

Таймкоды основаны на той же нормализованной WAV-копии, которую использует распознавание: цитата ведёт к этому месту записи. Исходный загруженный файл также сохранён и доступен для скачивания. Части одной реплики оператора не превращаются в разные первые ответы из-за паузы или ограничения длины ASR-фрагмента. Текст целиком можно скачать в TXT с ролями и таймкодами.

Для Linux/macOS установите `scripts/requirements-audio.txt` в `.local/audio-python`, запустите `PYTHONPATH=.local/audio-python python3 scripts/setup_audio.py`, а в `.env` укажите `CQA_PYTHON=python3`.

Если Ollama уже установлен:

```powershell
ollama pull qwen3.5:9b
# Ollama должен обслуживать http://127.0.0.1:11434
npm start
```

Для переносимой установки Windows в папку проекта:

```powershell
./scripts/setup-local.ps1
./scripts/start-local.ps1
```

Первый скрипт загружает официальный архив и проверяет SHA-256. Второй запускает Ollama без видимого фонового окна, хранит модели в `.local/models`, отключает облачный режим, скачивает выбранную модель и запускает приложение. Загрузка модели — несколько гигабайт. Повторный запуск продолжает загрузку Ollama pull. Если сервер Ollama уже работает, скрипт его не перезапускает; приложение всё равно проверяет метаданные каждой модели перед передачей транскрипта.

Для меньшего расхода памяти можно выбрать `qwen3.5:4b`: загрузите её через Ollama, затем выберите в разделе «Локальная модель». Это другой кандидат; его качество нужно измерять отдельно. На машинах с 8 ГБ VRAM запуск 9B зависит от длины контекста, драйвера и доступной памяти. Если получена ошибка памяти, уменьшите модель; не обрезайте транскрипт незаметно.

## Модель и честные ограничения

Первый кандидат — [Qwen3.5 9B](https://huggingface.co/Qwen/Qwen3.5-9B), доступный в [официальной библиотеке Ollama](https://ollama.com/library/qwen3.5). Это универсальная открытая модель с многоязычной поддержкой, **не модель, обученная специально на чек-листе Freedom**. Правила задаются текущей конфигурацией, правильность ответов надо проверять на собственной разметке и контрольном наборе.

Рассмотрены специализированные модели-судьи [Prometheus 2](https://huggingface.co/prometheus-eval/prometheus-7b-v2.0) и [M-Prometheus](https://arxiv.org/abs/2504.04953). Их специализация не доказывает точность на этих восьми критериях и RU/KZ/EN. Поэтому они не объявлены победителями без сравнения. Казахская адаптация [ISSAI Qwen3.5-9B-Kazakh](https://huggingface.co/issai/Qwen3.5-9B-Kazakh) — дополнительный кандидат для отдельного эксперимента, а не основание подменять оценки.

Для каждой оценки сохраняются тег и digest модели, версия Ollama, версия инструкции, хеш чек-листа и исходного диалога, длительность и количество токенов. API отклоняет облачные псевдонимы по метаданным Ollama. Обрезание входа и сдвиг контекста запрещены; превышение лимита приводит к видимой ошибке, а не оценке неполного диалога.

Для неизменённых официальных критериев контакта, выявления потребности и консультации после общей оценки выполняются отдельные проверки фактов и применимости N/A. Семантическая правка критерия отключает соответствующую специальную проверку; новый текст оценивается по текущему правилу. Сохранены этапы вычисления и расход токенов; итоговые веса всегда рассчитывает программа. Маленький сравнительный эксперимент и его ограничения описаны в [docs/quality-experiment.md](docs/quality-experiment.md). Проверка завершения не заменена экспериментальным вариантом, поскольку он ухудшил отложенные результаты.

Практические приоритеты команды перед защитой: [docs/winning-priorities.md](docs/winning-priorities.md).

Официальный Ground Truth не предоставлен в репозитории. Автоматические тесты подтверждают расчёты и процессы, **не процент точности модели**. Фактическую правильность тарифов и процедур нельзя независимо подтвердить без справочника компании. Звук доступен для ручного прослушивания; дикция и интонация автоматически не оцениваются.

## Расчёт

`total = round(100 × sum(weight × normalized_answer) / sum(applicable_weight), 2)`.

Да/Нет → 1/0, консультация → ответ/20, ведение → ответ/10. N/A исключается; флаг нарушения не участвует. Округляется только итог. Контрольный пример: c2/c3=N/A, c1/c5/c7=Да, c4=15, c6=7 → **85.38**.

## Проверка и пакетный прогон

```powershell
npm test
npm run check
npm run evaluate -- RU 3
npm run evaluate -- KZ 3
npm run evaluate -- EN 3
```

Последние команды отправляют реальные запросы локальной модели через работающий сервер. Они сохраняют результаты и завершаются с ненулевым кодом при ошибке любого диалога. Тесты сервера используют явно внедрённый тестовый адаптер только в тестах; приложение такой режим не имеет.

Для измерения качества используйте 18 вручную размеченных диалогов для настройки и 12 отложенных (с балансом RU/KZ/EN), отдельно проверяйте N/A, грубые ошибки, точность доказательств и абсолютную ошибку общего балла. Собственная разметка не равна официальному Ground Truth.

## Данные и воспроизводимость

`.env`, `.local/`, исходные записи, подписанный URL датасета, скачанные веса и результаты игнорируются Git. Данные приложения — `.local/state.json`. Для переноса состояния скопируйте этот файл отдельно и обращайтесь с ним как с исходными данными организаторов. Не запускайте два сервера с одним файлом состояния.

Приложение слушает только loopback; авторизация отсутствует согласно заданию. Это локальный прототип, его нельзя просто открыть в интернет без добавления контроля доступа. Удалённый сервер Sites не публикуется: браузерный облачный сервер не сможет безопасно использовать Ollama на вашем ноутбуке.

После изменения критерия сохраняется новая версия. Оценивание всегда запускается заново. Старые версии и результаты доступны в истории; апелляция изменяет только пересмотренный ответ. Экспорт содержит исходную и финальную оценку, включая решения проверяющего.

## Структура

- `server/rubric.mjs` — официальная начальная конфигурация.
- `server/domain.mjs` — проверка входа, доказательств и точная арифметика.
- `server/model.mjs` — инструкция, JSON Schema, защита локального инференса.
- `server/store.mjs` — атомарное сохранение состояния.
- `server/app.mjs` — API, очередь, апелляции и версии.
- `public/` — интерфейс без внешних ресурсов.
- `docs/api.md` — контракт API; `docs/spec.md` — требования.

## Защита за пять минут

1. Импорт нового диалога и запуск оценки.
2. Критерий → реальная реплика → причина; пример N/A и расчёт.
3. Апелляция → решение → новый итог при сохранённом исходном.
4. Изменение критерия через интерфейс → новая версия → настоящая переоценка.

На 23-м часу загрузите контрольную группу, выполните пакет и проверьте все 10 ID. До 24-го часа сделайте commit **и push**. После стоп-кода используйте интерфейс зафиксированной версии, не меняйте код.

## Сдача результатов

Команда **orleugpt**. Обязательная выгрузка по формату организаторов:

```powershell
npm run submit -- dev --evaluate
npm run submit -- prod --input .local/prod.json --evaluate
```

Получаются `results/dev/results.json` и `results/prod/results.json`. Для PROD нужен настоящий контрольный набор из 10 чатов. Команда проверяет формат и сохраняет ошибки обработки явно; push выполняется отдельно. [Инструкция сдачи и последний час](docs/submission.md). Внутренний экспорт интерфейса — другой формат.
